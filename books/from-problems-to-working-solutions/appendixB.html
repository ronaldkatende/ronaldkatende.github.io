Reproducing the Computational Examples

This appendix describes the supplied source package. The book’s numerical files are teaching demonstrations unless a specific chapter explicitly documents observed data. No programme downloads confidential records or silently replaces invented examples with real observations.

Directory structure and basic environment

The editable package contains main.tex, chapter files in chapters/, figures in figures/, Python programmes in code/, generated tabular outputs in generated/, the reference list and a requirements file. The source package includes its compiled PDF so that readers can inspect the edition without compiling it first.

A standard Python 3 installation with numpy, pandas, matplotlib and scikit-learn, in versions compatible with requirements.txt, supports the earlier examples. The four new chapter programmes use Python’s standard library. The LaTeX document uses a conventional pdfLaTeX toolchain with common mathematical and graphical packages. Package installation depends on the local operating system; institutions should test a reproducible environment before teaching.

python -m pip install -r requirements.txt
python code/reproduce_chapters.py
python code/reproduce_extensions.py
python code/ch09_impact_evaluation.py
python code/ch10_service_reliability.py
python code/ch11_transport_audit.py
python code/ch12_integrated_capstone.py
python code/test_chapters_09_12.py
latexmk -pdf -interaction=nonstopmode main.tex

For an offline installation, download approved installation files in advance and verify their provenance; install locally with the Python packaging tool’s offline options. A facility is not required to use a paid cloud platform or GPU for the supplied teaching scripts. Some live-data extensions require data access and separate permission; they are not prerequisites for the synthetic demonstrations.

The exact seeded output for Chapter 9 is recorded in generated CSV files; its sample estimate is not expected to equal the data-generating effect exactly. Chapter 10’s simulated availability values approximate, but need not exactly equal, the analytic values. The checks are designed to catch accidental changes and distinguish deterministic mathematical results from Monte Carlo estimates.

Evidence classification in filenames and captions

Do not name a synthetic results file real_impact.csv or describe it as field-tested in a figure caption. Suggested prefixes are synthetic_, public_observed_, partner_restricted_ and pilot_evaluated_, used only when their meaning is actually supported. A filename is not evidence, but clear naming reduces confusion when tables are copied between drafts.

When a real public dataset replaces a teaching fixture, record its source, licence, retrieval date, original checksum and transformation script. When protected institutional data are analysed, keep raw records in an authorised environment and distribute only permitted aggregates, synthetic fixtures and reproducible methods. A synthetic fixture generated to imitate a real system is still synthetic.

A compact reproducibility report

For each computational result report:

  1. the question, outcome and mathematical formulation;

  2. the provenance of all inputs and the reason each is admissible;

  3. software and dependency versions, machine characteristics where performance is claimed, and random seeds;

  4. an exact executable command and expected output file;

  5. comparisons with a hand calculation or independent implementation;

  6. sensitivity, missingness and failure-case checks;

  7. what is proved, measured, simulated or merely hypothesised;

  8. the limits on use in real service decisions.

A result is reproducible when an independent reader can follow the steps and obtain the claimed output from authorised inputs. It is not necessarily accurate about the physical world. Verification of computation and validation of the underlying model remain distinct (Sandve et al. 2013; Oberkampf and Roy 2010).

Working with low-bandwidth teaching laboratories

A lecturer can distribute the source package by local storage, extract it on student computers and use the synthetic fixtures without internet. Begin with a printed table and a short hand calculation. Students should then run the script, compare outputs and explain a deliberate failure condition. This sequence remains educational even if a machine cannot install a large scientific library. More advanced work with live environmental or survey data can be an extension for institutions with appropriate access and permissions.
